# 6.1 — HTTP Listener: Configuration Deep Dive

The **HTTP Listener** is an inbound source. It starts a flow when a client such as Postman sends an HTTP request to the configured host, port, and path.

> **Official Studio screenshots:** The MuleSoft documentation includes genuine Anypoint Studio screenshots of the Listener's Path, global configuration (Host/Port), Base Path, Allowed Methods, and advanced settings. [Open the official Listener configuration guide](https://docs.mulesoft.com/http-connector/latest/http-listener-ref#configure-http-listener-connection).

## Where the settings live

Listener settings are split between:
1. **Listener operation properties** — path, allowed methods, response behavior.
2. **Global Listener Configuration** — host, port, protocol, base path, and connection/TLS settings.

## 1. General tab

| Field | What it means | Example |
|---|---|---|
| Display name | Friendly label shown on the flow canvas | `Listener` |
| Connector configuration | Reference to a global HTTP Listener configuration | `HTTP_Listener_config` |
| Path | Endpoint path handled by this listener | `/hello` |

### Path examples

- `/hello` — exact path.
- `/customers/{customerId}` — captures a path parameter, available as `attributes.uriParams.customerId`.
- `/files/*` — wildcard route for matching additional path segments, where supported by the path pattern.

The final URL combines protocol, host, port, base path (if set), and listener path. For example, host `localhost`, port `8081`, no base path, and path `/hello` gives `http://localhost:8081/hello`.

## 2. Global Listener Configuration

Click the **+** beside Connector configuration to create a global configuration, or select an existing one.

| Field | Purpose | Beginner example |
|---|---|---|
| Name | Identifier referenced by Listener operations | `HTTP_Listener_config` |
| Protocol | HTTP or HTTPS | HTTP for local practice |
| Host | Network interface/address to bind | `localhost` for local-only testing; `0.0.0.0` to listen on all interfaces |
| Port | TCP port for incoming requests | `8081` |
| Base path | Shared prefix for listeners using this config | `api/v1` |

**Important:** Use `localhost` when you only need local requests. Binding to `0.0.0.0` exposes the listener on all network interfaces; use it only when needed and secure the application appropriately. HTTPS requires TLS configuration.

## 3. Advanced tab

Common settings include:

- **Allowed methods:** Restricts which HTTP methods this listener accepts, for example `GET` or `GET,POST`. If not configured, the Listener can accept all methods.
- **Response streaming mode:** Controls how response bodies are streamed. `AUTO` is the typical default; `ALWAYS` streams; `NEVER` avoids streaming and may require buffering/consuming the body.
- **Read timeout:** Maximum wait for request data to be read, in milliseconds. Use a value appropriate for the payload and client.
- Other connection and parsing options can vary by HTTP Connector version.

Do not change advanced values just because they exist. Start with defaults and change them to meet a clear requirement.

## 4. Responses tab

The Listener can customize the HTTP response returned when the flow completes.

- **Response:** Configure response body, status code, headers, and reason phrase.
- **Error Response:** Configure the response for an error raised by the flow.

For example, a successful flow can return status `200` with a body; an API that creates a resource may deliberately return `201`. Choose status codes according to the API contract.

## 5. What arrives in the Mule event?

When Listener receives a request:
- The HTTP request body becomes `payload`.
- HTTP metadata becomes `attributes`, including method, headers, query parameters, and URI parameters.

Useful expressions:
- `#[attributes.method]`
- `#[attributes.headers]`
- `#[attributes.queryParams]`
- `#[attributes.uriParams.customerId]`

## XML example

Studio generates XML similar to this for a basic listener:

```xml
<http:listener-config name="HTTP_Listener_config">
    <http:listener-connection host="localhost" port="8081" />
</http:listener-config>

<flow name="helloFlow">
    <http:listener config-ref="HTTP_Listener_config" path="/hello" />
    <logger level="INFO" message="Request received at /hello" />
    <set-payload value="Hello from MuleSoft!" />
</flow>
```

Exact XML can vary by connector/runtime version. Prefer the Studio visual editor if you are new to Mule.
