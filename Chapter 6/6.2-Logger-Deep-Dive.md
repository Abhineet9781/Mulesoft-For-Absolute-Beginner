# 6.2 — Logger: Configuration Deep Dive

The **Logger** is a Mule Core component used to write diagnostic messages to the application logs. In Anypoint Studio, messages normally appear in the Console; deployed applications write to their configured log output.

> **Configuration reference:** [Official MuleSoft Logger Component documentation](https://docs.mulesoft.com/mule-runtime/4.12/logger-component-reference). The reference documents the Logger fields and XML configuration; the exact Studio layout may differ slightly by version.

## Logger fields

| Field | Purpose | Example |
|---|---|---|
| Display name | Label shown on the canvas | `Logger` |
| Message | Text and/or DataWeave expression to log | `Request received` |
| Level | Severity level | `INFO` |
| Category | Optional logger category/name for filtering | `com.example.hello` |

### Message examples

Static message:

```text
Request received by helloFlow
```

Log the payload:

```text
Payload received: #[payload]
```

Log the HTTP method:

```text
HTTP method: #[attributes.method]
```

Logger is one of the components that allows a message to mix ordinary text and Mule expressions. For more complex value construction elsewhere in a flow, use DataWeave expressions.

## Log levels

| Level | Typical use |
|---|---|
| ERROR | A serious failure requiring attention |
| WARN | Unexpected or potentially harmful condition |
| INFO | Useful application lifecycle/business milestones |
| DEBUG | Detailed troubleshooting information |
| TRACE | Very detailed diagnostic information |

Log-level visibility also depends on the application's logging configuration. A DEBUG Logger may not appear if the logging configuration filters DEBUG messages.

## Example configuration

```xml
<logger
    level="INFO"
    doc:name="Log Incoming Request"
    message="Request received. Method: #[attributes.method]" />
```

A typical flow:

```xml
<flow name="helloFlow">
    <http:listener config-ref="HTTP_Listener_config" path="/hello"/>
    <logger level="INFO" message="Request received at /hello"/>
    <set-payload value="Hello from MuleSoft!"/>
</flow>
```

## Best practices

- Use a meaningful message that tells you what happened.
- Prefer INFO for important milestones and DEBUG for detailed diagnostics.
- Do not log passwords, access tokens, API keys, payment data, or personal data unnecessarily.
- Avoid logging a huge payload on every request; it can increase log volume and expose sensitive information.
- Add correlation identifiers when you need to trace a request across multiple flows/services.

## Practice

1. Add a Logger immediately after HTTP Listener.
2. Set Level to INFO and Message to `Request received`.
3. Run the app and call the endpoint from Postman.
4. Check the Studio Console.
5. Change the message to include `#[attributes.method]` and send the request again.
