# 6.6 — Set Payload: Configuration Deep Dive

**Set Payload** replaces the current Mule message payload with a value. It is useful for simple response bodies and small expressions. Use Transform Message for complex mapping logic.

> **Official reference:** [Set Payload Transformer](https://docs.mulesoft.com/mule-runtime/4.12/set-payload-transformer-reference) documents Value, MIME Type, and Encoding.

## Studio fields

| Field | Purpose | Example |
|---|---|---|
| Display name | Label shown on the canvas | `Set Payload` |
| Value | Literal value or DataWeave expression | `Hello from Mule` |
| MIME Type | Optional output media type | `text/plain` or `application/json` |
| Encoding | Optional character encoding | `UTF-8` |

Exact field visibility can vary by Studio/runtime version.

## Example 1: plain text

Value:

```text
Hello from my Mule application!
```

This replaces the current payload with that text.

## Example 2: expression

Value:

```dataweave
#[ 'Hello! Current time: ' ++ now() as String ]
```

An expression begins with `#[ ... ]`. Keep expressions simple; use Transform Message when the output needs a more involved mapping.

## Example 3: JSON response

You can set a JSON object with an expression and specify the appropriate MIME type in the component configuration:

```dataweave
#[{
  message: "success",
  count: 3
}]
```

Set MIME Type to `application/json` when appropriate. For a full DataWeave transformation with explicit output format, Transform Message is often clearer.

## XML example

```xml
<set-payload value="Hello from MuleSoft!" mimeType="text/plain" encoding="UTF-8"/>
```

For a dynamic expression, Studio may generate:

```xml
<set-payload value="#['Hello ' ++ vars.firstName]" mimeType="text/plain"/>
```

## What changes after Set Payload?

- The payload is replaced by the configured value.
- Attributes are not automatically replaced just because the payload changes.
- Variables remain available.
- If the flow was triggered by HTTP Listener, the Listener commonly returns the final payload as the response body unless response settings override that behavior.

## Common mistakes

- Setting a JSON-looking string but leaving the payload MIME type inconsistent with the intended response.
- Expecting Set Payload to preserve the old payload automatically.
- Using it for a large/complex mapping that should be in Transform Message.
- Forgetting that a later component may replace the payload again.

## Practice

1. Create Listener path `/hello`.
2. Add Set Payload with `Hello from MuleSoft!`.
3. Set MIME Type to `text/plain`.
4. Run the app and call `GET http://localhost:8081/hello` from Postman.
5. Change the payload to a JSON object and inspect the response headers and body.
