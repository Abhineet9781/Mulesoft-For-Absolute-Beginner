# 5.3 — HTTP Methods: GET, POST, PUT, PATCH, DELETE

An HTTP method tells the server what kind of action the client wants to perform on a resource. You select the method in Postman, and your Mule flow or the API it calls handles that request.

Imagine an API that manages customers at `/customers`.

| Method | Typical purpose | Example |
|---|---|---|
| GET | Read or retrieve data | `GET /customers` |
| POST | Create a resource or submit data for processing | `POST /customers` |
| PUT | Replace a resource, usually at a known identifier | `PUT /customers/42` |
| PATCH | Partially update a resource | `PATCH /customers/42` |
| DELETE | Delete a resource | `DELETE /customers/42` |

These are common conventions; an API's documentation defines its actual behavior.

## GET

Use **GET** to retrieve information. A GET request usually does not include a request body.

Example: `GET http://localhost:8081/customers`

A Mule application can read query parameters or call another API and return the result.

## POST

Use **POST** to create a resource or submit data for processing. The request commonly includes a body, often JSON.

Example body:

```json
{
  "name": "Asha",
  "city": "Delhi"
}
```

In Postman, choose **Body → raw → JSON** when the endpoint expects JSON. The server may also require a `Content-Type: application/json` header.

## PUT

Use **PUT** when the API's contract says the submitted representation replaces the resource at the specified URI. For example, `PUT /customers/42` might replace customer 42's editable fields.

## PATCH

Use **PATCH** for a partial update, such as changing only a customer's city. Exact patch format and behavior depend on the API.

## DELETE

Use **DELETE** to request deletion of a resource. The API may return a status such as `200 OK`, `202 Accepted`, or `204 No Content`, depending on its design.

## Important concepts

- **Idempotency:** GET, PUT, and DELETE are defined as idempotent methods in HTTP semantics; repeating the same request is intended to have the same effect on server state. POST is not generally idempotent. PATCH is not guaranteed to be idempotent.
- **Status codes matter:** A successful HTTP exchange does not always mean the status is `200`. For example, creation may return `201 Created`, and a successful response with no body may return `204 No Content`.
- **Listener vs Request:** An HTTP Listener receives a request and starts a flow. An HTTP Request operation sends a request from the flow to another service.

## Practice in Postman

1. Choose a method from the dropdown.
2. Enter the URL and path.
3. For POST, PUT, or PATCH, add a body if the API requires one.
4. Click **Send** and inspect the status code, response headers, and response body.
