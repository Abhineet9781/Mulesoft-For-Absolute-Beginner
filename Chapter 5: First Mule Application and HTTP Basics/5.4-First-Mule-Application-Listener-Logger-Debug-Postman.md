# 5.4 — Build and Debug Your First Mule Application

In this lesson, you will create a small Mule application with an HTTP Listener and a Logger, run it in Anypoint Studio, call it from Postman, and inspect execution using the debugger.

## Goal

Create this flow:

```text
Postman
   │  GET http://localhost:8081/hello
   ▼
HTTP Listener → Logger
   │
   ▼
HTTP response
```

The Listener starts the flow. The Logger writes a message to the Studio console/logs. If no explicit response payload is set, the listener can return the event's current payload; for a predictable response, you may optionally add Set Payload after Logger.

## 1. Create a Mule project

1. Open Anypoint Studio.
2. Create a new Mule project (for example, `FirstMuleApplication`).
3. Open the project's main Mule configuration file in the visual flow editor.
4. If prompted, select or confirm a Mule Runtime version supported by your Studio installation.

## 2. Add HTTP Listener

1. Drag **HTTP → Listener** onto the canvas. It should be the first component and act as the flow source.
2. Create or select a Listener Configuration.
3. Set the host to `0.0.0.0` if you want the service to listen on the machine's network interfaces, or use the appropriate local setting for your environment. For a local-only beginner exercise, follow the default shown by your Studio version.
4. Set the port to `8081`.
5. Set the path to `/hello`.

Your endpoint will commonly be:

```text
http://localhost:8081/hello
```

If port 8081 is already occupied, select another free port and update the URL used in Postman.

## 3. Add Logger

1. Drag **Core → Logger** after the Listener.
2. Set its message to:

```text
Hello endpoint was called
```

3. Save the project.

**Optional:** Add **Set Payload** after Logger and set its value to `Hello from my first Mule application!`. This makes the response body explicit and predictable. Without it, the response depends on the event's current payload and the listener's response configuration.

## 4. Run the application

1. Save all files.
2. Right-click the project and choose **Run As → Mule Application** (the exact menu wording can vary slightly by Studio version).
3. Open the Console view and wait for deployment to complete.
4. Check the console for startup errors. If the configured port is in use, resolve the port conflict and run again.

To stop the application, use the stop/terminate control in the Console or Servers view, depending on your Studio version.

## 5. Call it from Postman

1. Open Postman and create an HTTP request.
2. Select **GET**.
3. Enter `http://localhost:8081/hello` (or your configured port/path).
4. Click **Send**.

You should receive an HTTP response. If you added Set Payload, the response body should be `Hello from my first Mule application!`. The Logger message should appear in the Studio Console/logs.

### If it does not work

- **Connection refused:** confirm the app is running and the port is correct.
- **404 / not found:** check the Listener path and the URL path.
- **Application fails to start:** inspect the Console for configuration errors or a port conflict.
- **Logger message not visible:** inspect the correct application's Console/log output and make sure the request reached the listener.

## 6. Reset the perspective in Studio

A **perspective** is an arrangement of views and editors for a task, such as developing or debugging.

If your views have moved or disappeared:

1. Switch to the Mule Design perspective or the perspective you normally use.
2. Open the perspective menu (commonly **Window → Perspective → Reset Perspective**).
3. Confirm the reset if prompted.

This restores the selected perspective's default layout; it does not reset your Mule project or delete your flow.

## 7. Run in Debug mode

Debugging lets you pause a running flow and inspect the Mule event as it moves through processors.

1. Stop the application if it is currently running normally.
2. Right-click the project and select **Debug As → Mule Application** (or the equivalent debug command in your Studio version).
3. Accept any prompt to switch to the Debug perspective.
4. Send the GET request from Postman again.

The application must be running in debug mode for breakpoints to pause execution.

## 8. Add a breakpoint

1. Open the flow in the visual editor.
2. Right-click the Logger processor (or another supported processor) and choose **Add Breakpoint**. The menu may vary by Studio version.
3. Send the request again from Postman.
4. Studio should pause when execution reaches that processor. Switch to the Debug view if prompted.

Use the debugger controls to resume, step through execution where supported, or terminate the debug session. Remove the breakpoint when you no longer need it.

## 9. Inspect the event and evaluate expressions

When execution is paused, use the Mule event/debug inspection panels available in your Studio version to inspect the current payload, attributes, and variables.

Common Mule expressions include:

- `#[payload]` — current message payload
- `#[attributes]` — current message attributes, such as HTTP request metadata
- `#[vars.greeting]` — a variable named `greeting`, if it has been set

If your Studio debugger provides an **Evaluate Expression** or equivalent expression view, evaluate expressions such as `payload` or `attributes` while paused. Some versions or debugging contexts may not expose a separate evaluation panel; in that case, use the Variables/event inspection views or add a temporary Logger to inspect a non-sensitive value.

Do not assume an expression evaluator accepts every DataWeave expression in every debugger context. Evaluate expressions only while the relevant event is suspended and available.

## Final checklist

- [ ] The Mule application starts without errors.
- [ ] The HTTP Listener uses the expected port and path.
- [ ] Postman can send a GET request to the endpoint.
- [ ] The Logger message appears in the Studio logs.
- [ ] You can reset the perspective without changing project files.
- [ ] You can run in Debug mode, pause at a breakpoint, and inspect the event.

You have now created, called, and debugged a basic Mule application. Next, you can add Set Payload, Set Variable, Transform Message, and HTTP Request to build more useful integration flows.
