# 18.4 — File Connector: Read CSV, Transform, and Write JSON

## Objective

Read employees.csv from a chosen input folder, convert each row to JSON with typed salary values, and write employees.json to an output folder.

## Suggested project structure

~~~text
src/main/resources/
  input/
    employees.csv
  output/
~~~

Create the required output directories. Use a project-relative or environment-specific path rather than committing an absolute personal path.

## Sample input

~~~csv
employeeId,firstName,department,salary
E001,Asha,Engineering,85000
E002,Ravi,Finance,72000
~~~

## Flow snapshot — Studio canvas

~~~mermaid
flowchart TD
    A[Scheduler or HTTP Listener for lab trigger] --> B[File Read: employees.csv]
    B --> C[Transform Message: CSV to JSON]
    C --> D[File Write: output/employees.json]
    D --> E[Logger: completion and count only]
    B -. read failure .-> F[Error Handler]
    D -. write failure .-> F
~~~

For a production file-arrival process, use the File Connector's supported listener/polling pattern for your version. This lab uses Read and Write operations to make transformation visible.

## File Read settings

- Operation: File Read.
- Path: input file path appropriate for your local environment.
- Reader MIME type: application/csv.
- Header: true because the sample contains a header.
- Consider streaming for large files.

The MIME type tells the reader how to parse file content; it does not perform the mapping.

## DataWeave

~~~dataweave
%dw 2.0
output application/json
---
payload map (row) -> {
  employeeId: row.employeeId,
  firstName: row.firstName,
  department: row.department,
  salary: row.salary as Number
}
~~~

## File Write settings

- Operation: File Write.
- Path: output/employees.json; resolve relative paths intentionally.
- Content: current payload.
- Output MIME type: application/json.
- Choose overwrite behavior explicitly.

## Mule XML teaching fragment

The following is a fragment, not a complete standalone app:

~~~xml
<file:read config-ref="File_Config"
           path="${app.home}/input/employees.csv"
           outputMimeType="application/csv"
           doc:name="Read employees CSV"/>
<ee:transform doc:name="CSV to JSON">
    <ee:message>
        <ee:set-payload><![CDATA[
%dw 2.0
output application/json
---
payload map (row) -> {
  employeeId: row.employeeId,
  firstName: row.firstName,
  department: row.department,
  salary: row.salary as Number
}
        ]]></ee:set-payload>
    </ee:message>
</ee:transform>
<file:write config-ref="File_Config"
            path="${app.home}/output/employees.json"
            doc:name="Write employees JSON"/>
~~~

Create File configuration and Mule namespaces through Studio. Verify relative-path resolution for your runtime; do not assume every path resolves from the same directory.

## Test checklist

1. Put the sample file in the input directory.
2. Run the flow.
3. Confirm the output file exists.
4. Validate JSON syntax.
5. Confirm salaries are numbers while IDs stay strings.
6. Repeat with a malformed salary and inspect the error path.
7. Repeat with an empty CSV file.
8. Repeat with a read-only output folder.

## Questions

1. Why set outputMimeType on File Read?
2. Why doesn't setting application/json on File Write map columns?
3. What is the difference between File Read and a file listener/polling flow?
4. How could the flow avoid overwriting a previous output?
5. What changes are needed for a large CSV?
6. Why externalize filesystem paths per environment?

## Extension

Write one output per input file with a safe filename strategy. Move processed input to an archive only after a successful write. Consider idempotency if the same file can arrive more than once.
