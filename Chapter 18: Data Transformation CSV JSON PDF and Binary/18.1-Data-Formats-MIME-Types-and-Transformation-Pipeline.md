# 18.1 — Data Formats, MIME Types, and the Transformation Pipeline

## 1. Start with the payload

In Mule 4, the payload may contain text, structured data, a stream, or binary bytes. Metadata can describe its media type and encoding. A DataWeave reader interprets the input; the script transforms values; a writer serializes the result.

## 2. Data format vs MIME type

| Common content | DataWeave format | Common MIME type |
|---|---|---|
| JSON text | json | application/json |
| CSV text | csv | application/csv |
| XML text | xml | application/xml |
| Generic bytes | binary | application/octet-stream |
| PDF document | Normally binary pass-through | application/pdf |
| Plain text | text | text/plain |

The exact HTTP response MIME type can depend on your API contract. For example, text/csv is commonly used for CSV downloads while DataWeave documents its CSV format as application/csv. Configure response media types intentionally.

## 3. Reader and writer responsibilities

A reader interprets input content. A writer serializes a value into an output representation. Setting a MIME type does not by itself transform the content.

~~~dataweave
%dw 2.0
output application/json
---
{
  message: "Hello",
  count: 2
}
~~~

CSV output example:

~~~dataweave
%dw 2.0
output application/csv header=true
---
[
  { id: 101, name: "Asha" },
  { id: 102, name: "Ravi" }
]
~~~

Expected CSV:

~~~csv
id,name
101,Asha
102,Ravi
~~~

## 4. Why CSV values often start as strings

Given:

~~~csv
id,quantity,active
0012,3,true
~~~

The CSV reader generally exposes row field values as strings. The value 0012 might be an identifier with meaningful leading zeros. Do not convert identifiers to numbers unless the business contract says they represent numeric quantities.

~~~dataweave
%dw 2.0
output application/json
---
payload map (row) -> {
  id: row.id,
  quantity: row.quantity as Number,
  active: row.active as Boolean
}
~~~

Validate untrusted values before casting; invalid casts need a deliberate error strategy.

## 5. Binary payloads

Binary data includes PDFs, images, archives, and other non-text content. Treat the payload as bytes unless a parser dedicated to that file format is available.

### Flow snapshot B — Choose the safe path

~~~mermaid
flowchart TD
    A[Incoming payload] --> B{Known structured text format?}
    B -- Yes --> C[Set or verify reader MIME type]
    C --> D[DataWeave parse and transform]
    B -- No --> E{Binary file?}
    E -- Yes --> F{Only forwarding or saving it?}
    F -- Yes --> G[Preserve bytes; set correct metadata]
    F -- No --> H[Use format-aware parser or document service]
    E -- No --> I[Inspect contract / encoding / metadata]
~~~

## 6. Common mistakes

- Changing only Content-Type while leaving content in a different format.
- Assuming CSV numeric-looking fields are already numbers.
- Returning binary bytes with application/json.
- Trying to parse a PDF as CSV or JSON.
- Building a PDF by changing the MIME type of JSON. A valid PDF must be generated by a PDF-capable tool, library, or service.
- Ignoring encoding and CSV delimiters, quoting, or header settings.
- Logging payloads that could contain secrets, personal data, or large binary content.
