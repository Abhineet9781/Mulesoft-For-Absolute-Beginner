# 16.12 — 30 Independent DataWeave Implementation Problems

These are **implementation tasks, not worked solutions**. Write each transformation yourself. Use JSON output unless the problem explicitly asks for another format. For each one, include a normal case and at least one edge-case test. Some tasks can be solved in more than one valid way.

## Level 1 — Core mapping

### Problem 1: Employee summary
Input contains `id`, `firstName`, `lastName`, `department`. Output `employeeId`, `fullName`, and `departmentName`. Trim the full name.

### Problem 2: Default contact information
Map a customer to `id`, `name`, `email`, and `phone`. Default missing email to null and missing phone to the string `"Not provided"`. Explain the difference.

### Problem 3: Numeric conversion
Input `quantity` and `unitPrice` may be numeric strings. Convert them to numbers and calculate `lineTotal`. Decide what should happen if either value is malformed.

### Problem 4: Email normalization
Trim and lowercase email addresses for a list of users. Preserve each user's ID and do not drop records with missing email; represent missing email consistently.

### Problem 5: Rename a nested structure
Convert `customer.address.postalCode` to `shippingAddress.postalCode` and map the other address fields. Decide how to handle a missing address.

## Level 2 — Arrays and collection functions

### Problem 6: Active users
Return only users where `active` is true. Test missing and null active values.

### Problem 7: Product price bands
Add a `priceBand` field: `LOW` below 25, `MEDIUM` from 25 through 100, and `HIGH` above 100. Define behavior for negative prices.

### Problem 8: Invoice lines
For each invoice line, output SKU, quantity, unit price, and line total. Return invoice ID at the top level and the sum of all line totals.

### Problem 9: Top three products
Sort products by sales descending and return the top three. Decide how to handle fewer than three records and equal sales values.

### Problem 10: Unique customer list
Remove duplicate customers by customer ID. Document which duplicate wins and why; do not leave that behavior accidental.

### Problem 11: Orders by status
Group orders by status and return a summary containing each status, count, and total order value.

### Problem 12: Flatten department employees
Each department has an array of employees. Output one record per employee including department ID, department name, employee ID, and employee name. Empty departments should not create fake employees.

### Problem 13: Aggregate by customer
Given orders with `customerId` and `total`, return one record per customer with order count, total spend, and average order value. Test no orders and null totals.

### Problem 14: Object-to-array conversion
Given an object of feature flags, return an array of `{name, enabled}` records sorted by name. Handle values that are not Boolean according to a documented policy.

### Problem 15: Reconcile two lists
Given an order list and a shipment list, use IDs to produce each order with shipment status or `NOT_SHIPPED`. Define how duplicate shipment IDs are resolved.

## Level 3 — Types, dates, and formats

### Problem 16: Date normalization
Convert dates from `dd/MM/yyyy` into `yyyy-MM-dd`. Return a clear failure strategy for invalid dates and test leap-day cases.

### Problem 17: Event timestamp
Normalize incoming event timestamps to a consistent ISO 8601 representation. Preserve timezone/offset semantics and explain how you treat inputs without an offset.

### Problem 18: CSV export
Transform customer objects into CSV with columns `customerId`, `fullName`, `email`, and `active`. Test commas, quotes, and missing values in text fields.

### Problem 19: XML order to JSON
Given namespaced XML containing an order and repeated line elements, create JSON with order ID and line objects. Use the actual namespace URI and test one versus many lines.

### Problem 20: Embedded JSON
A field contains JSON serialized as text. Parse it, retain the outer record ID, and return a structured error when the embedded JSON is malformed. Do not silently replace invalid data with an empty object.

## Level 4 — Business transformations

### Problem 21: Discount engine
Calculate discount by customer tier: Bronze 0%, Silver 5%, Gold 12%, Platinum 18%. Handle unknown tiers and ensure the discount cannot exceed the subtotal.

### Problem 22: Tax and rounding
Calculate line subtotals, tax, and invoice total. State the currency precision and whether you round per line or only at invoice level. Test values such as 0.1 and 19.99.

### Problem 23: API response envelope
Transform a downstream response into `{success, data, meta}`. Map upstream error responses to a predictable error object without leaking internal stack traces.

### Problem 24: Validation report
For each submitted customer, validate required ID, name, email, and country. Return valid records and a separate array of rejected records with row index and all validation messages.

### Problem 25: Inventory availability
Given order lines and an inventory lookup, calculate available-to-promise quantities and mark each line as `AVAILABLE`, `PARTIAL`, or `OUT_OF_STOCK`. Do not mutate inventory or assume duplicate SKUs are unique unless validated.

## Level 5 — Intermediate integration scenarios

### Problem 26: CRM to ERP customer mapping
Convert a CRM customer payload to an ERP schema. Normalize names, map address fields, convert IDs/types, omit optional fields per the target contract, and add a source-system marker.

### Problem 27: Multi-source customer enrichment
Combine a customer payload with a lookup object from `vars`. Match on customer ID, preserve the original record when enrichment is absent, and mark the enrichment status.

### Problem 28: Build a product catalog
Group products by category. Within each category, sort by price and return count, minimum price, maximum price, and product summaries. Test empty categories and null prices.

### Problem 29: Event normalization
Normalize three possible incoming event shapes into one canonical schema: event ID, event type, occurred-at timestamp, entity ID, and attributes. Use pattern matching or explicit conditions; unknown event shapes must be surfaced.

### Problem 30: End-to-end order transformation
Input includes customer, order header, and line items. Output a target-system request containing customer reference, order metadata, normalized line items, subtotal, discount, tax, final total, and correlation ID from `vars`. Define behavior for missing required data and invalid line values.

## Required acceptance criteria for every problem

- The script has a valid DataWeave 2.0 header and correct output MIME type.
- The output matches a written schema and business rule.
- The happy path is tested.
- At least two edge cases are tested, including missing/null/empty data where relevant.
- Numeric/date conversion failures have a deliberate strategy.
- No sensitive data is written to logs.
- The code is readable: meaningful names, no unnecessary repeated work, and comments for non-obvious rules.

## Suggested scoring rubric

| Criterion | Points |
|---|---:|
| Correct output structure and types | 3 |
| Business logic and edge cases | 3 |
| Robust null/type/error handling | 2 |
| Readability and maintainability | 1 |
| Tests and explanation | 1 |
| **Total per problem** | **10** |

A strong intermediate learner should be able to implement most Level 1–3 problems independently and solve Level 4–5 with documentation and testing. Revisit the earlier lessons when a function or type is unfamiliar.
