# 16.3 — Selectors, Arrays, Objects, and Paths

Selectors read values from the input. Learn the input structure first; selectors do not search the whole payload magically.

## 1. Object selectors

Given `payload.customer.name`, each dot selects a key in the current object. Quoted selectors handle keys that are not identifiers: `payload."customer-id"`.

```dataweave
%dw 2.0
output application/json
---
{
  id: payload.customer.id,
  city: payload.customer.address.city,
  externalId: payload."external-id"
}
```

If a parent key is missing or null, a direct selector can fail. Use safe navigation, defaults, or validation based on the desired contract.

## 2. Array index selectors

Array indices are zero-based. `payload.items[0]` selects the first item. Indexing an empty array or a missing index needs explicit handling.

```dataweave
%dw 2.0
output application/json
var items = payload.items default []
---
{
  firstItem: if (sizeOf(items) > 0) items[0] else null,
  itemCount: sizeOf(items)
}
```

## 3. Multi-value selectors

The `.*field` selector selects a field from each matching object in an array-like structure. Example:

```dataweave
%dw 2.0
output application/json
---
payload.orders.*total
```

Given orders containing total values, the result is an array of totals. This is concise, but use `map` when you also need to rename fields, calculate values, or handle each record differently.

## 4. Descendant selector

The `..name` descendant selector finds matching keys at nested levels. It is powerful but can return values from several branches and levels. Avoid using it when the schema has multiple unrelated fields with the same name; explicit paths are safer for contract mappings.

## 5. Mapping arrays

```dataweave
%dw 2.0
output application/json
---
(payload.items default []) map (item, index) -> {
  position: index + 1,
  sku: item.sku,
  amount: item.quantity * item.unitPrice
}
```

The second lambda argument is the index. It is zero-based; add one for a human-facing sequence number.

## 6. Object fields and dynamic keys

Use a computed key expression for dynamic property names:

```dataweave
%dw 2.0
output application/json
---
{
  (payload.region): {
    count: sizeOf(payload.records default [])
  }
}
```

Dynamic keys should be deliberate. If the key comes from external input, consider normalization and collision behavior.

## 7. Filtering array records

```dataweave
%dw 2.0
output application/json
---
(payload.users default []) filter ((user) -> user.active == true)
```

Filtering keeps the original matching elements. To transform the survivors, chain `filter` and `map`, or map only after filtering.

## 8. Practical nested transformation

Input:
```json
{
  "customer": {"id": 9, "name": "Isha"},
  "orders": [
    {"id": "O-1", "total": 40},
    {"id": "O-2", "total": 70}
  ]
}
```

Script:
```dataweave
%dw 2.0
output application/json
---
{
  customerId: payload.customer.id,
  customerName: payload.customer.name,
  orderIds: payload.orders.*id,
  totalSpend: sum(payload.orders.*total)
}
```

## Practice examples

### Example 5 — Extract names from departments

```dataweave
%dw 2.0
output application/json
---
(payload.departments default []) flatMap ((department) -> department.employees default [])
  map ((employee) -> employee.name)
```

### Example 6 — Safe first match

```dataweave
%dw 2.0
output application/json
var active = (payload.users default []) filter ((u) -> u.active == true)
---
if (isEmpty(active)) null else active[0]
```

## Common mistakes

- Confusing `payload.items.name` with a map across array items.
- Assuming index 1 is the first array element.
- Using descendant selection where a stable path is available.
- Assuming a field exists in every record.
- Forgetting that selectors preserve the selected values' types.
