## Build the worked application

1. Create registration-api with Listener path /register on port 8081.
2. Send POST http://localhost:8081/register with JSON fields name and email.
3. Add Transform Message with the example below. It returns a validation result in the body; it does not yet set an HTTP 4xx status.
4. Add a Logger after the transform with message #["Registration request processed"]. Avoid logging personal data.
5. Test missing name, missing email, and a valid body.

## Worked example

Use the relevant example below while building the tutorial application. Create global configurations through Studio and let Studio manage generated configuration IDs.

```text
%dw 2.0
output application/json
var name = payload.name default ""
var email = payload.email default ""
---
if (isEmpty(trim(name)) or isEmpty(trim(email)))
  { success: false, message: "Both name and email are required" }
else
  { success: true, message: "Registration request is valid", user: { name: name, email: email } }
```

**Do not copy the worked example directly.** Start a new flow or project, define expected inputs and outputs first, implement it yourself, and test both normal and edge cases in Postman. The challenge intentionally has no screenshot and no solution.

## Troubleshooting checklist

- Confirm the Listener port is available and the app is running.
- Match the HTTP method and route exactly.
- For JSON requests, use Postman Body → raw → JSON.
- Query parameters are available under attributes.queryParams; URI template values are under attributes.uriParams.
- payload is the current message body, vars contains variables, and attributes describes the current message.
- HTTP Request replaces the current payload with its response unless you preserve the original data in a variable first.
