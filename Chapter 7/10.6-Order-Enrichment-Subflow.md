## Build the worked application

1. Create order-enrichment-api with Listener path /orders/{orderId} on port 8081.
2. Add Set Variable orderId with value #[attributes.uriParams.orderId].
3. Add Flow Reference and create a subflow named build-order-summary.
4. Inside the subflow, add Logger message #["Enriching order " ++ vars.orderId], then Set Payload with a JSON expression.
5. Call GET http://localhost:8081/orders/ORD-2007 and confirm the response contains the ID and status.
6. Variables and attributes remain available because a subflow processes the same Mule event.

## Worked example

Use the relevant example below while building the tutorial application. Create global configurations through Studio and let Studio manage generated configuration IDs.

```text
XML shape:
<flow name="order-enrichment-flow">
  <http:listener config-ref="HTTP_Listener_config" path="/orders/{orderId}"/>
  <set-variable variableName="orderId" value="#[attributes.uriParams.orderId]"/>
  <flow-ref name="build-order-summary"/>
</flow>
<sub-flow name="build-order-summary">
  <logger level="INFO" message="#[&quot;Enriching order &quot; ++ vars.orderId]"/>
  <set-payload value="#[{ orderId: vars.orderId, status: &quot;RECEIVED&quot; }]"/>
</sub-flow>
```

## Troubleshooting checklist

- Confirm the Listener port is available and the app is running.
- Match the HTTP method and route exactly.
- For JSON requests, use Postman Body → raw → JSON.
- Query parameters are available under attributes.queryParams; URI template values are under attributes.uriParams.
- payload is the current message body, vars contains variables, and attributes describes the current message.
- HTTP Request replaces the current payload with its response unless you preserve the original data in a variable first.
