## Build the worked application

1. Create customer-integration-api with Listener POST /customers on port 8081.
2. Add Set Variable requestSource with value #[attributes.headers.'x-source' default 'postman']. Optionally send header x-source: training from Postman.
3. Add Transform Message to normalize the customer name and email using the example below. Extend it to validate required fields before making the outbound call.
4. Add INFO Logger message #["Customer request received from " ++ vars.requestSource]. Do not log the full customer body.
5. Add HTTP Request configured for HTTPS host postman-echo.com, method POST, path /post, with JSON content type and the normalized payload as body.
6. Add Transform Message after Request to return a concise confirmation instead of the entire echoed response.
7. Test with Postman. If outbound internet is unavailable, temporarily bypass Request and return the normalized customer object.

## Worked example

Use the relevant example below while building the tutorial application. Create global configurations through Studio and let Studio manage generated configuration IDs.

```text
Sample request:
{
  "name": "  Anika Sharma  ",
  "email": "anika@example.com"
}

Normalization DataWeave:
%dw 2.0
output application/json
---
{
  name: trim(payload.name default ""),
  email: lower(trim(payload.email default ""))
}
```

## Troubleshooting checklist

- Confirm the Listener port is available and the app is running.
- Match the HTTP method and route exactly.
- For JSON requests, use Postman Body → raw → JSON.
- Query parameters are available under attributes.queryParams; URI template values are under attributes.uriParams.
- payload is the current message body, vars contains variables, and attributes describes the current message.
- HTTP Request replaces the current payload with its response unless you preserve the original data in a variable first.
