# 7.1 — Employee Greeting API

GET /hello; Listener, Set Variable, Set Payload, Logger.

## Build the worked application

1. Create a Mule project named employee-greeting-api and a flow named employee-greeting-flow.
2. Add HTTP Listener. Create a global config with Host 0.0.0.0 and Port 8081; set Path to /hello.
3. Add Set Variable: Name greetingName, Value expression #["MuleSoft Learner"].
4. Add Set Payload with Value expression #["Hello, " ++ vars.greetingName ++ "! Your first Mule API is running."].
5. Add Logger with Level INFO and Message #[payload].
6. Run the app and send GET http://localhost:8081/hello in Postman. Expect status 200 and the greeting text; check the Studio console.

## Worked example

Use the relevant example below while building the tutorial application. Create global configurations through Studio and let Studio manage generated configuration IDs.

```text
Core XML shape:
<flow name="employee-greeting-flow">
  <http:listener config-ref="HTTP_Listener_config" path="/hello"/>
  <set-variable variableName="greetingName" value="#[&quot;MuleSoft Learner&quot;]"/>
  <set-payload value="#[&quot;Hello, &quot; ++ vars.greetingName ++ &quot;! Your first Mule API is running.&quot;]"/>
  <logger level="INFO" message="#[payload]"/>
</flow>
```

## Troubleshooting checklist

- Confirm the Listener port is available and the app is running.
- Match the HTTP method and route exactly.
- For JSON requests, use Postman Body → raw → JSON.
- Query parameters are available under attributes.queryParams; URI template values are under attributes.uriParams.
- payload is the current message body, vars contains variables, and attributes describes the current message.
- HTTP Request replaces the current payload with its response unless you preserve the original data in a variable first.
