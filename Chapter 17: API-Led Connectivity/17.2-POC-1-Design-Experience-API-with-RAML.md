# 17.2 — POC 1: Design the Experience API in RAML

This is the contract-first part of the first POC. You will write a RAML 1.0 contract for the Experience API, validate the shape, and then import it into Anypoint Studio in the next lesson.

## 1. Define the contract before implementing it

The consumer needs one operation:

`GET /customers/{customerId}/summary`

- A valid ID returns the channel-friendly customer summary.
- An unknown ID returns HTTP 404 with a structured error.
- The response is JSON.
- The contract declares the shape; implementation still must enforce the behavior.

## 2. RAML 1.0 contract

Create a file named `customer-experience-api.raml` locally and paste the following content. Save it as UTF-8. Do not include Markdown code fences in the actual `.raml` file.

```yaml
#%RAML 1.0
title: Customer Experience API
description: Customer summary API for a web or mobile consumer.
version: v1
baseUri: http://localhost:8083/api
mediaType: application/json
protocols:
  - HTTP

types:
  OrderSummary:
    type: object
    properties:
      orderCount:
        type: integer
        minimum: 0
      totalValue:
        type: number
        minimum: 0
      currency:
        type: string
        minLength: 3
        maxLength: 3

  CustomerSummary:
    type: object
    properties:
      id: string
      name: string
      email?: string
      membershipStatus: string
      orderSummary: OrderSummary

  ApiError:
    type: object
    properties:
      code: string
      message: string
      correlationId?: string

/customers/{customerId}/summary:
  uriParameters:
    customerId:
      type: string
      minLength: 1
      example: C-100
  get:
    description: Retrieve a customer summary with order totals.
    responses:
      200:
        body:
          application/json:
            type: CustomerSummary
            example:
              id: C-100
              name: Asha Sharma
              email: asha@example.com
              membershipStatus: ACTIVE
              orderSummary:
                orderCount: 2
                totalValue: 1499.5
                currency: INR
      404:
        body:
          application/json:
            type: ApiError
            example:
              code: CUSTOMER_NOT_FOUND
              message: No customer exists for the supplied ID.
```

## 3. Read the important parts

- `#%RAML 1.0` identifies the RAML version.
- `baseUri` describes the API base URL used by the mock and local implementation.
- `types` defines reusable response structures.
- `uriParameters` documents the customer ID in the path.
- `responses` documents successful and not-found outcomes.
- `example` is representative sample data, not a database record.

The contract does not define how the System API fetches a customer, how the Process API calculates totals, or how authentication is enforced. Those responsibilities belong to implementation and runtime configuration.

## 4. Validate the contract

Use the RAML editor or API Designer/Design Center available to your organization to check syntax and review the example against the declared type. If a validator reports a syntax issue, resolve it before scaffolding the project. Wizard availability depends on your Anypoint access and Studio version.

## 5. Try contract-first questions

Before importing, answer:

1. Which response body belongs to HTTP 200?
2. Which response body belongs to HTTP 404?
3. What happens if `email` is absent?
4. Does declaring `ApiError` automatically send a 404 at runtime?
5. Which parts of this contract are specific to the mobile/web consumer?

Expected reasoning: RAML describes the documented interface. It does not itself execute error logic or guarantee the running application returns the declared status.

## 6. Acceptance checklist

- [ ] The file begins with `#%RAML 1.0`.
- [ ] The base URI uses port 8083 and base path `/api`.
- [ ] The resource path includes `{customerId}`.
- [ ] The success and not-found responses have documented JSON shapes.
- [ ] The types and examples agree.
- [ ] You can explain why this is an Experience API contract rather than a System API contract.
