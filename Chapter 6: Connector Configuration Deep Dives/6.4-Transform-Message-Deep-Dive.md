# 6.4 — Transform Message: Configuration Deep Dive

**Transform Message** uses DataWeave to transform the current payload into a new structure or format. It is the preferred component for mappings and non-trivial transformations.

## What you see in the Studio editor

Depending on Studio/DataWeave version and editor mode, you may see:
- **Input tree:** structure of the incoming payload.
- **Output tree:** desired output structure.
- **Mapping lines:** visual mapping between input and output fields.
- **DataWeave source:** script that defines the transformation.
- **Preview:** sample output produced from sample input.

If metadata is unknown, Studio may not show a useful tree until you provide sample data or metadata. The DataWeave source is still available.

## Example: transform JSON

Input payload:

```json
{
  "firstName": "Asha",
  "lastName": "Sharma",
  "city": "Delhi"
}
```

DataWeave script:

```dataweave
%dw 2.0
output application/json
---
{
  fullName: payload.firstName ++ " " ++ payload.lastName,
  location: payload.city,
  status: "active"
}
```

Output:

```json
{
  "fullName": "Asha Sharma",
  "location": "Delhi",
  "status": "active"
}
```

## Important settings and concepts

- **Output directive:** `output application/json` declares the output MIME type/format.
- **DataWeave script:** the logic after the header and separator `---`.
- **Input metadata:** describes the structure/type of incoming data; it improves visual mapping and preview.
- **Output metadata:** describes the target structure/type.
- **Preview data:** sample input used by Studio to show expected output; it is not a live production request.
- **MIME type:** output format such as JSON, XML, or text.

The editor's tabs and layout may differ by Studio version. Do not confuse a sample preview with the actual payload of a running request.

## Transform Message vs Set Payload

Use **Set Payload** for a simple value or short expression. Use **Transform Message** for mapping fields, restructuring objects/arrays, filtering, formatting, and other DataWeave transformations.

## Common mistakes

- Forgetting the DataWeave header `%dw 2.0`.
- Forgetting the output directive.
- Referencing a field that does not exist in the input.
- Assuming preview data is the same as runtime data.
- Building a complex transformation inside Set Payload instead of using Transform Message.

## Practice

1. Create a flow that receives a JSON request through HTTP Listener.
2. Add Transform Message.
3. Use the sample input above and write the script.
4. Send matching JSON from Postman.
5. Compare the actual response with the Studio preview.
