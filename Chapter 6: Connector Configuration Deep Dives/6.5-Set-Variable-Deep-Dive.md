# 6.5 — Set Variable: Configuration Deep Dive

**Set Variable** creates or updates a variable on the Mule event. A variable can hold a string, number, object, payload snapshot, or another value needed later in the flow.

> **Official reference:** [MuleSoft Set Variable Transformer](https://docs.mulesoft.com/mule-runtime/4.4/variable-transformer-reference). The page documents the variable name, value, and related configuration.

## Studio fields

| Field | Purpose | Example |
|---|---|---|
| Display name | Label on the canvas | `Set Variable` |
| Name / Variable Name | Identifier for the variable | `greeting` |
| Value | Literal value or DataWeave expression | `Hello Mule` |

Variable names should be simple identifiers using letters, numbers, and underscores; begin with a letter or underscore for clarity. Refer to a variable with `vars.variableName`.

## Example

Set Variable:
- Name: `greeting`
- Value: `Hello from MuleSoft`

Read it later in a Logger message:

```text
Greeting value: #[vars.greeting]
```

Or use it in DataWeave:

```dataweave
%dw 2.0
output application/json
---
{
  message: vars.greeting
}
```

## Variable vs payload vs attributes

| Item | What it represents | Expression |
|---|---|---|
| Payload | Main message content | `payload` |
| Attributes | Metadata from the source/operation | `attributes` |
| Variables | Values stored during processing | `vars.greeting` |

Setting a variable does **not** replace the payload. A variable belongs to the Mule event and is available to later processors in that event. When a flow reference passes the event to another flow/subflow, variables are part of that event; be mindful when changing a variable's value.

## XML example

```xml
<set-variable variableName="greeting" value="Hello from MuleSoft" />
<logger level="INFO" message="Greeting: #[vars.greeting]" />
```

For an expression value, Studio may generate an expression such as:

```xml
<set-variable variableName="requestMethod" value="#[attributes.method]" />
```

## Best practices

- Use descriptive names such as `customerId`, `originalPayload`, or `requestMethod`.
- Save the original payload in a variable before a transformation if later logic needs it.
- Do not use variables as a replacement for proper application state or persistent storage.
- Avoid complex data transformations inside Set Variable; use Transform Message for that.
- Avoid storing secrets unless necessary and protect them from logs.

## Practice

1. Add Set Variable after Listener.
2. Set `requestMethod` to `#[attributes.method]`.
3. Add Logger with `Incoming method: #[vars.requestMethod]`.
4. Call the endpoint and confirm the method is logged.
