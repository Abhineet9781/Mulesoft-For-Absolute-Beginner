# 5.2 — Understanding localhost, Port, and Path

When you call a Mule application from Postman, you use a URL. A URL tells the client which computer to contact and which endpoint to request.

Example:

```text
http://localhost:8081/hello
```

| Part | Meaning |
|---|---|
| `http://` | Protocol used for the request |
| `localhost` | The same computer on which the client is running |
| `:8081` | Port number where the application is listening |
| `/hello` | Path handled by the HTTP Listener |

## What is localhost?

**localhost** refers to the computer you are currently using. It commonly resolves to the loopback network interface, so a request to `localhost` goes back to your own machine rather than to a public server.

If Mule Runtime is running on your computer and Postman is running on that same computer, `localhost` is usually the correct host. If Postman is running on a different computer or inside a separate container/virtual machine, `localhost` refers to that environment instead; you may need a reachable host address and appropriate network settings.

## What is a port?

A **port** identifies a network service on a host. Think of the host as the building and the port as a particular entrance.

For a local Mule application, port `8081` is a common example, but it is not mandatory. The Listener Configuration in Studio determines which port the application uses. If another process is already using that port, the application may fail to start; choose a free port and use the same port in Postman.

## What is a path?

A **path** identifies the endpoint within the server, for example `/hello` or `/customers`. The path configured on the HTTP Listener must match the path you call from Postman.

If your listener path is `/hello`, this URL matches:

```text
http://localhost:8081/hello
```

This URL does not match that exact path:

```text
http://localhost:8081/goodbye
```

## Troubleshooting checklist

- Confirm the Mule application is running.
- Confirm the host and port match the Listener Configuration.
- Confirm the request path matches the Listener path.
- If the application cannot start, check whether the port is already in use.
- If Postman is not on the same machine as Mule Runtime, do not assume its `localhost` points to the Mule machine.
