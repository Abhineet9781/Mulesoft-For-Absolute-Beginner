# 5.1 — Basic Connectors and Components in Anypoint Studio

In MuleSoft, a **Mule event** moves through a flow. Components receive the event, read or change its data, and pass it to the next step.

A simple flow might look like this:

```text
HTTP Listener → Logger → Set Variable → Set Payload → Transform Message
```

Not every flow needs every component. Start with the components below, then combine them as the use case requires.

## 1. HTTP Listener

The **HTTP Listener** is an inbound message source. It starts a flow when an HTTP request reaches the configured host, port, and path.

- Commonly used to expose an endpoint that Postman or another client can call.
- Configure a Listener Configuration, including the port, then set a path such as `/hello`.
- A listener is a source, so it is normally placed at the beginning of an HTTP-triggered flow.

Example endpoint: `http://localhost:8081/hello`

## 2. Logger

The **Logger** writes a message to the Mule application logs. It is useful for understanding the path a request takes and checking values while developing.

Example message:

```text
Request received by the Hello flow
```

You can also log an expression, for example `#[payload]`, to inspect the current payload. Avoid logging passwords, access tokens, or other sensitive data.

## 3. Set Variable

**Set Variable** stores a value in a named Mule event variable. Use it when you need to keep a value available to later processors in the same event.

Example:
- Variable name: `greeting`
- Value: `Hello from MuleSoft`

Reference it later with `#[vars.greeting]`.

A variable is not the payload: setting a variable does not replace the message body.

## 4. Set Payload

**Set Payload** replaces the current message payload with a value you choose.

Example value:

```text
Hello from my first Mule application!
```

The payload is the main content being processed. If the flow ends after Set Payload, that value can become the HTTP response body when the listener is configured to return the event payload.

## 5. Transform Message

**Transform Message** transforms data, commonly using **DataWeave**. It is often used to map fields, change formats, and construct JSON, XML, or text output.

Example DataWeave script to produce a JSON object:

```dataweave
%dw 2.0
output application/json
---
{
  message: "Hello from MuleSoft",
  status: "success"
}
```

This produces a JSON payload. DataWeave expressions can also read values from `payload`, `vars`, and attributes.

## 6. HTTP Request

The **HTTP Request** operation is an outbound connector: it lets a Mule flow call another HTTP endpoint. Unlike HTTP Listener, it does not start the flow.

Typical configuration includes:
- Host and port (or a base URL) of the external service
- Path to call
- HTTP method, such as GET or POST
- Headers, query parameters, or a body when required

For example, a flow can receive a request through HTTP Listener, call another API using HTTP Request, and then return or transform that API's response. Configure connection details and error handling for the service you call.

## Quick comparison

| Component | Main purpose | Common use |
|---|---|---|
| HTTP Listener | Starts a flow from an inbound HTTP request | Expose an endpoint |
| Logger | Writes a message to application logs | Troubleshooting |
| Set Variable | Stores a value in an event variable | Reuse a value later |
| Set Payload | Replaces the event payload | Build a response/body |
| Transform Message | Transforms data using DataWeave | Map or reshape data |
| HTTP Request | Calls an external HTTP endpoint | Consume another API |

## Beginner practice

1. Create a Mule project in Anypoint Studio.
2. Add an HTTP Listener and configure a path such as `/hello`.
3. Add a Logger after the Listener.
4. Add Set Payload after the Logger with a short text response.
5. Save and run the application, then call the endpoint from Postman.
