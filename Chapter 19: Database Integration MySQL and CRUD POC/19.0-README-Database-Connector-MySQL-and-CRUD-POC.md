## POC overview — Employee Management API

Build a Mule app on port 8081 and a MySQL schema called `mule_learning`.

| Method | Endpoint | Operation | Purpose |
|---|---|---|---|
| POST | `/api/employees` | Insert | Create employee |
| GET | `/api/employees` | Select | List employees |
| GET | `/api/employees/{id}` | Query Single | Fetch one employee |
| PUT | `/api/employees/{id}` | Update | Change an employee |
| DELETE | `/api/employees/{id}` | Delete | Remove an employee |
| GET | `/api/employees/search?department=...` | Select with parameters | Filter by department |
| POST | `/api/employees/bulk` | Bulk Insert | Insert multiple employees |

## Architecture

~~~mermaid
flowchart LR
    C[Postman / curl] --> H[HTTP Listener]
    H --> V[Validate request]
    V --> M[DataWeave / parameter mapping]
    M --> D[Database Connector]
    D --> Q[(MySQL: mule_learning)]
    Q --> D
    D --> R[Transform DB result to API JSON]
    R --> C
~~~

## What you will learn

- JDBC, host/port/database, credentials, drivers, and Test Connection.
- MySQL Connector configuration in Database Config.
- Select, Query Single, Insert, Update, Delete, Bulk Insert/Update/Delete, Stored Procedure, Execute DDL, Execute Script, and database listener/source concepts.
- Parameterized SQL, SQL injection prevention, result metadata, generated keys, and row counts.
- Transactions, rollback, connection pooling, reconnection, timeouts, and least-privilege database users.
- How to validate inputs, map database rows into API responses, handle not found, and test with Postman/curl.

## Important scope note

This is a learning POC, not a production template. The examples use placeholder properties and local MySQL. Do not commit actual database passwords, connection strings containing secrets, or production data. Validate Mule XML, connector versions, driver compatibility, and the DataWeave expressions in your own Anypoint Studio/runtime before deployment.
