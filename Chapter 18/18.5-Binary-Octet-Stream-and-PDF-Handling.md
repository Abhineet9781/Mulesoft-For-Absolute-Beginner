# 18.5 — Binary, Octet-Stream, and PDF Handling

## Objective

Handle an uploaded or downloaded PDF as bytes, preserve its original content when forwarding, and understand when a PDF-aware library or service is required.

## Core distinction

A PDF is a document format with a binary file structure. Mule can transport its bytes through the message payload, but reading a PDF file as binary does not automatically extract its visible text. DataWeave's binary format is intended for binary content such as images and PDFs.

- application/pdf: use when the bytes are known to be a PDF.
- application/octet-stream: generic binary media type when the file type is unknown or the API contract uses it.
- application/json: only if the body actually contains JSON.
- Base64 text: encoded bytes carried inside text/JSON; not the same representation as raw binary.

## Flow snapshot A — receive and forward PDF unchanged

~~~mermaid
flowchart TD
    A[HTTP Listener: POST /files/pdf] --> B[Validate size and expected file type]
    B --> C[Keep payload as bytes or stream]
    C --> D[HTTP Request to downstream service or File Write]
    D --> E[Return appropriate status and media type]
    B -. validation fails .-> F[400 or 413 response]
~~~

The upload contract matters. A raw PDF body differs from multipart/form-data. For multipart, select the file part before forwarding its binary content.

## Flow snapshot B — read PDF from disk and return it

~~~mermaid
flowchart LR
    A[HTTP Listener: GET /files/sample.pdf] --> B[File Read: sample.pdf]
    B --> C[Preserve binary payload]
    C --> D[HTTP Response: Content-Type application/pdf]
    D --> E[Client downloads or displays PDF]
~~~

## Minimal Mule flow pattern

1. Configure an HTTP Listener route such as GET /files/sample.pdf.
2. Use File Read on a known test PDF.
3. Keep the payload unchanged.
4. Set the HTTP response Content-Type to application/pdf.
5. Return the payload as the response body.
6. Test by saving the response to a file and opening it with a PDF viewer.

~~~text
HTTP Listener (GET /files/sample.pdf)
  -> File Read (test/sample.pdf)
  -> No text Transform Message needed
  -> HTTP response body = binary payload
~~~

The exact File Read output representation depends on connector configuration. Choose a representation that preserves the bytes, then verify end-to-end by opening the returned file or comparing size/hash. Avoid logging the full binary payload.

## Pass-through is not PDF transformation

| Requirement | Correct approach |
|---|---|
| Forward PDF unchanged | Preserve bytes and set accurate response metadata |
| Save PDF to disk | File Write with binary content, preserving bytes |
| Download PDF from a remote API | HTTP Request, retain body bytes and media type |
| Extract PDF text | Use a PDF parser/library or dedicated document service |
| Merge or split pages | Use a PDF-aware tool/library/service |
| Redact content | Use a PDF-aware redaction method |
| Generate new PDF from data | Use a PDF-generation library or service |

Changing Content-Type changes how a receiver interprets the body; it does not rewrite the file format.

## Binary DataWeave example

DataWeave supports binary output with application/octet-stream. This is useful for binary handling, but it is not a PDF generator.

~~~dataweave
%dw 2.0
output application/octet-stream
---
payload
~~~

Use only when the incoming value and desired output are appropriate binary data. For unchanged PDF pass-through, a transformation is usually unnecessary.

## Download test

Use this command to save only the response body and keep headers separately:

~~~bash
curl -sS -D response-headers.txt \
  "http://localhost:8081/files/sample.pdf" \
  -o sample-downloaded.pdf
~~~

Open sample-downloaded.pdf. Verify that it opens and that the response Content-Type is accurate.

## Safety and reliability checklist

- Set upload size limits and validate expected content type.
- Do not trust file extensions alone.
- Avoid logging raw bytes, personal information, or large files.
- Use safe filenames; never trust a client filename as a filesystem path.
- Account for streaming and memory pressure with large documents.
- Use authentication and authorization for sensitive files.
- Handle missing files, downstream timeouts, permission errors, and partial writes.
- Do not treat PDF bytes as text, even if a log viewer renders scattered printable characters.
