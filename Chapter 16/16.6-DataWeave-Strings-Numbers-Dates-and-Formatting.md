# 16.6 — Strings, Numbers, Dates, and Formatting

Integrations often fail at boundaries: one system sends a date as text, another expects a timestamp; one sends a decimal as a string; another expects a numeric JSON value. Normalize deliberately.

## 1. String operations

Common tools include `trim`, `upper`, `lower`, `splitBy`, `joinBy`, `contains`, `startsWith`, `endsWith`, `replace`, and regular-expression matching/replacement functions.

```dataweave
%dw 2.0
output application/json
---
{
  normalized: lower(trim(payload.email default "")),
  tags: (payload.tagsText default "") splitBy ",",
  label: (payload.tags default []) joinBy " | ",
  hasPrefix: startsWith(payload.code default "", "ORD-")
}
```

If whitespace around split tokens matters, trim each token. Be clear about whether empty tokens should be retained or discarded.

## 2. Regex basics

Regex can validate or extract patterns, but do not use a complex expression when a simple string operation is clearer. Test valid, invalid, empty, and Unicode input. A format check is not necessarily business validation.

Example concept: normalize repeated whitespace, or check whether an identifier follows a known pattern. Keep the actual regex documented and test it against counterexamples.

## 3. Numeric conversion and rounding

```dataweave
%dw 2.0
output application/json
var quantity = (payload.quantity default "0") as Number
var unitPrice = (payload.unitPrice default "0") as Number
var subtotal = quantity * unitPrice
---
{
  subtotal: subtotal,
  formattedSubtotal: subtotal as String {format: "0.00"}
}
```

Use `round`, `ceil`, or `floor` when the business rule calls for it. Formatting as a string is not the same as rounding a number for calculations. Define currency and scale rules with stakeholders.

## 4. Date, DateTime, LocalDateTime

- `Date`: calendar date without a time.
- `Time`: time of day.
- `DateTime`: timestamp with date/time and timezone context.
- `LocalDateTime`: date/time without a timezone offset.

Do not treat a local date/time as a globally unambiguous instant. For cross-system events, agree on timezone and offset conventions, usually ISO 8601.

```dataweave
%dw 2.0
output application/json
var orderDate = payload.orderDate as Date {format: "yyyy-MM-dd"}
---
{
  isoDate: orderDate as String {format: "yyyy-MM-dd"},
  year: orderDate.year,
  month: orderDate.month,
  day: orderDate.day
}
```

## 5. Formatting timestamps

```dataweave
%dw 2.0
output application/json
var timestamp = payload.createdAt as DateTime
---
{
  sourceTimestamp: timestamp,
  formatted: timestamp as String {format: "yyyy-MM-dd'T'HH:mm:ssXXX"}
}
```

The input parser must match the actual source format. Avoid silently dropping timezone information. Confirm formatting tokens against DataWeave's date/time format documentation.

## 6. Numeric and date comparisons

Normalize both sides to comparable types before comparing. Comparing a string such as `"100"` to a number may not mean what the business expects. Similarly, compare date values, not arbitrary formatted date strings, unless lexicographic ordering is guaranteed by a fixed ISO format.

## 7. Example — parse a CSV-style date and amount

```dataweave
%dw 2.0
output application/json
---
{
  invoiceDate: payload.invoiceDate as Date {format: "MM/dd/yyyy"},
  amount: (payload.amount as Number) as String {format: "0.00"}
}
```

## Checklist

- Is the source format known?
- Can a value be blank, malformed, or null?
- Is timezone information present and meaningful?
- Is the result meant to be a number or a display string?
- What rounding and precision rules apply?
