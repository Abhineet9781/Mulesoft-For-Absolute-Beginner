# 16.1 — DataWeave Fundamentals, Syntax, and Execution

## 1. What DataWeave does

DataWeave (DW) is MuleSoft's functional language for selecting, calculating, filtering, and transforming data. A common integration converts an upstream JSON payload into the structure expected by a downstream API, while normalizing types and handling missing values.

Example: input `{ "firstName": "Asha", "lastName": "Rao" }` becomes `{ "fullName": "Asha Rao" }`.

## 2. The standard script shape

```dataweave
%dw 2.0
output application/json
---
{
  message: "Hello, " ++ "MuleSoft",
  ready: true
}
```

- `%dw 2.0` declares the language version.
- `output application/json` declares the output media type.
- `---` separates the header from the body expression.
- The expression after `---` produces the result.

A script can also declare imports, namespaces, types, variables, and functions in its header. Keep declarations above the separator.

## 3. Expressions, not statements

Most DataWeave constructs evaluate to values. An object literal returns an object; a conditional returns one of its branch values; a function call returns its result.

```dataweave
%dw 2.0
output application/json
var amount = 120
---
{
  amount: amount,
  eligible: amount >= 100,
  message: if (amount >= 100) "Eligible" else "Not eligible"
}
```

Inside an object, `amount: amount` means the key is `amount` and the value is the variable named `amount`. The key and variable may share a name.

## 4. Data formats and output types

The output directive controls serialization:
- `application/json`: JSON
- `application/xml`: XML
- `application/csv`: CSV
- `text/plain`: text

Input can be JSON, XML, CSV, Java objects, or other supported formats. In Mule, metadata and the reader/writer settings influence how data is interpreted. A JSON object and a JSON string containing object-shaped text are not the same thing.

## 5. Objects, arrays, strings, and literals

```dataweave
%dw 2.0
output application/json
---
{
  customer: { id: 42, active: true },
  tags: ["new", "priority"],
  note: null,
  count: 3,
  price: 19.95
}
```

Object keys can be unquoted when they are valid identifiers. Quote keys with spaces or punctuation, for example `"order-status": "OPEN"`. Strings use double quotes. Arrays use square brackets and object literals use braces.

## 6. Concatenation and arithmetic

Use `++` to concatenate strings or combine compatible values. Use arithmetic operators such as `+`, `-`, `*`, and `/` for numbers.

```dataweave
%dw 2.0
output application/json
var first = "Data"
var second = "Weave"
---
{
  language: first ++ second,
  lineTotal: 3 * 12.5,
  discounted: 100 * 0.9
}
```

Do not rely on implicit coercion when combining unlike types. Convert values deliberately (see 16.2).

## 7. The payload and Mule event

In a Mule Transform Message component, `payload` refers to the current event payload. `attributes` refers to source metadata (for example HTTP request attributes), and `vars` refers to flow variables. DataWeave can read all three when available:

```dataweave
%dw 2.0
output application/json
---
{
  request: payload,
  sourcePath: attributes.requestPath default null,
  correlationId: vars.correlationId default null
}
```

Available attributes vary by source connector and runtime context. Do not assume an HTTP-specific attribute exists in a scheduler or messaging flow.

## 8. Comments and readability

```dataweave
// One-line comment
/*
 Multi-line comment
*/
%dw 2.0
output application/json
---
{ status: "OK" }
```

Put comments above non-obvious business rules, not on every line. Prefer named intermediate values over one huge expression.

## 9. Debugging a script

When a preview fails, check:
1. Is the script header valid?
2. Does the declared output format match the intended result?
3. Is the input actually the shape assumed by the script?
4. Does a selector target a missing field?
5. Is a string being treated as a number or date?
6. Does a function receive the expected type?

Use representative input metadata and realistic sample data. A preview that passes for one happy-path payload does not prove the mapping is robust.

## Worked examples

### Example 1 — Create a greeting

```dataweave
%dw 2.0
output application/json
---
{ greeting: "Hello, " ++ (payload.name default "learner") ++ "!" }
```

Input: `{ "name": "Asha" }`; result: `{ "greeting": "Hello, Asha!" }`.

### Example 2 — Build a response envelope

```dataweave
%dw 2.0
output application/json
---
{
  success: true,
  data: payload,
  meta: { source: "customer-api" }
}
```

This wraps the original payload without changing the nested data.
