# 16.10 — DataWeave Inside Mule Flows and Testing

## 1. Where DataWeave appears

In Mule 4, DataWeave expressions are used in Transform Message, Set Payload, Set Variable, connector parameters, choice conditions, logger messages, and other expression-enabled fields. Transform Message is best for a complete payload transformation; small expressions are appropriate for small values.

## 2. Transform Message workflow

1. Identify the source payload and its actual format.
2. Identify the target contract and media type.
3. Add representative input metadata/sample data.
4. Build the smallest correct mapping.
5. Preview output.
6. Test null, missing, empty, malformed, and boundary values.
7. Run the flow and verify the actual connector request/response.
8. Add automated tests.

A green preview only verifies the preview scenario; it does not prove that runtime metadata, real connector attributes, or all edge cases match.

## 3. Set Payload and Set Variable

A Set Payload expression replaces the current payload. A Set Variable expression stores a computed value in `vars` without replacing the payload. Use variables for intermediate values that are needed later in the flow, not as a substitute for clear transformation design.

Example Set Variable expression:
```dataweave
%dw 2.0
output application/java
---
(payload.order.lines default []) reduce ((line, total = 0) ->
  total + (line.quantity * line.unitPrice)
)
```

The output MIME type matters: connector metadata and subsequent expressions can behave differently depending on whether the result is serialized JSON or a native Java value.

## 4. HTTP request mapping

When calling a downstream API, transform to the exact request body contract and set the correct headers, such as `Content-Type: application/json`. Do not assume that changing a payload's shape automatically sets every HTTP header correctly. Verify the outbound request with logs or a test server, without exposing secrets.

## 5. MUnit tests

Test the transformation through a flow test or an isolated component test. Cover:
- Happy path.
- Missing optional field.
- Missing required field.
- Explicit null.
- Empty array/object.
- Invalid number/date.
- Unexpected enum value.
- Large or nested input.
- Correct output type and HTTP status where relevant.

Keep expected outputs readable and compare meaningful structure, not unstable formatting where possible.

## 6. Test-first example

Input:
```json
{"quantity":"3","unitPrice":"12.50","discountRate":0.1}
```

Expected conceptual output:
```json
{"quantity":3,"unitPrice":12.5,"subtotal":37.5,"discount":3.75,"total":33.75}
```

Implementation:
```dataweave
%dw 2.0
output application/json
var quantity = payload.quantity as Number
var unitPrice = payload.unitPrice as Number
var subtotal = quantity * unitPrice
var discount = subtotal * (payload.discountRate default 0)
---
{
  quantity: quantity,
  unitPrice: unitPrice,
  subtotal: subtotal,
  discount: discount,
  total: subtotal - discount
}
```

## 7. Troubleshooting table

| Symptom | Likely cause | First check |
|---|---|---|
| Selector error | Wrong path or null parent | Inspect input structure |
| Cannot coerce value | Invalid source representation | Check input type and format |
| Missing output key | Conditional omission or wrong selector | Check branch conditions |
| Array/object mismatch | Wrong collection function | Confirm expected result shape |
| Date shifted | Timezone parsing/formatting | Check offset and target semantics |
| XML field absent | Namespace or repeated-element issue | Inspect XML and namespace URI |
| CSV columns wrong | Writer settings or inconsistent row shape | Verify header and row objects |
| Preview differs from runtime | Metadata/input differs | Test with real event data |

## 8. Before shipping

- Confirm output schema and MIME type.
- Avoid hardcoded credentials and sensitive logs.
- Decide error handling at both mapping and Mule flow levels.
- Measure performance with realistic payload sizes.
- Put transformations under source control and automated tests.
- Document assumptions and business rules.
