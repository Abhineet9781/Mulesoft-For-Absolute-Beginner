# 16.2 — Types, Coercion, Null, and Defaults

Correct transformations depend on knowing whether a value is a string, number, Boolean, date, array, object, or null. Many production defects are type mismatches disguised as simple mapping errors.

## 1. Common types

Examples include `String`, `Number`, `Boolean`, `Null`, `Array`, `Object`, `Date`, `DateTime`, `LocalDateTime`, `Time`, and `Binary`. Type availability and exact coercion behavior depend on the DataWeave version and context.

```dataweave
%dw 2.0
output application/json
type Customer = {
  id: Number,
  name: String,
  active: Boolean
}
var c: Customer = { id: 7, name: "Mina", active: true }
---
c
```

Named types document expectations and can be reused. They do not automatically validate every external payload unless the transformation or connector path actually applies the type constraints.

## 2. Coercion with `as`

Use `as` to convert a value to a target type when a valid conversion exists.

```dataweave
%dw 2.0
output application/json
var quantity = "4" as Number
var enabled = "true" as Boolean
---
{ quantity: quantity, nextQuantity: quantity + 1, enabled: enabled }
```

A conversion can fail if the source text is invalid. Do not convert arbitrary external strings without deciding how invalid values should be handled.

Date parsing commonly uses a format:
```dataweave
%dw 2.0
output application/json
---
{
  date: "2026-10-25" as Date {format: "yyyy-MM-dd"},
  amount: "123.45" as Number
}
```

## 3. Missing vs null vs empty

These are distinct:
- **Missing key:** object has no such property.
- **Null:** property exists with a null value.
- **Empty string:** `""`.
- **Empty array:** `[]`.
- **Empty object:** `{}`.

Do not collapse these distinctions unless the business contract says they are equivalent.

## 4. Default operator

`default` supplies a fallback when the left side is absent or null:

```dataweave
%dw 2.0
output application/json
---
{
  displayName: payload.name default "Unknown",
  tags: payload.tags default [],
  retries: payload.retryCount default 0
}
```

Use defaults intentionally. A default can hide upstream data quality issues, so for required business fields it may be better to validate and return a clear error.

## 5. Safe navigation and conditional selection

The `?` operator can test whether an object contains a key. Safe navigation with `?.` is useful when a parent may be null. For example, `payload.customer?.address` avoids dereferencing a null customer. Verify exact syntax in the runtime's DataWeave version.

```dataweave
%dw 2.0
output application/json
---
{
  hasEmail: payload.customer.email?,
  city: payload.customer?.address?.city default "Not supplied"
}
```

The `email?` key-presence test differs from `email != null`: a key may exist with a null value.

## 6. Type checks and validation

```dataweave
%dw 2.0
output application/json
---
{
  isArray: payload.items is Array,
  isNumber: payload.total is Number,
  hasItems: (payload.items default []) is Array
}
```

Use explicit validation for required fields and meaningful messages. A type check is not a complete business validation: an order total can be a number and still be negative.

## 7. Optional object fields

Use conditional object entries when a field should be omitted rather than emitted as null:

```dataweave
%dw 2.0
output application/json
var email = payload.email default null
---
{
  id: payload.id,
  name: payload.name
  ++ (if (email != null and email != "") { email: email } else {})
}
```

The example demonstrates object combination. For larger mappings, build the object with clear conditional sections and test the exact output shape. If your contract requires `email: null`, include the key explicitly instead of omitting it.

## 8. Number precision and money

For financial values, define rounding rules, scale, currency, and whether rounding happens per line or only at the final total. Do not assume a binary floating-point representation is appropriate for every financial calculation.

```dataweave
%dw 2.0
output application/json
var line = 19.99 * 3
---
{
  rawLineTotal: line,
  displayLineTotal: line as String {format: "0.00"}
}
```

Formatting a number for display is different from changing the underlying numeric value. Follow the API's numeric schema and the business's rounding policy.

## Practice examples

### Example 3 — Normalize inconsistent input

```dataweave
%dw 2.0
output application/json
---
{
  id: (payload.id default "0") as Number,
  name: trim((payload.name default "") as String),
  active: (payload.active default false) as Boolean
}
```

### Example 4 — Report field presence

```dataweave
%dw 2.0
output application/json
---
{
  emailProvided: payload.email?,
  phoneProvided: payload.phone?,
  emailValue: payload.email default null
}
```

## Checklist

- Which values can be absent or null?
- Which fields are required by the target API?
- Are numeric strings allowed?
- What happens when a cast fails?
- Should a missing optional field be omitted, defaulted, or emitted as null?
