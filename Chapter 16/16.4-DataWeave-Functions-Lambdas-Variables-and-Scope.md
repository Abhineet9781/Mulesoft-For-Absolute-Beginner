# 16.4 — Functions, Lambdas, Variables, and Scope

## 1. Variables

Declare reusable values in the header:

```dataweave
%dw 2.0
output application/json
var subtotal = payload.quantity * payload.unitPrice
var tax = subtotal * 0.08
---
{ subtotal: subtotal, tax: tax, total: subtotal + tax }
```

Variables are expressions, not mutable storage. Treat them as named calculations. A variable declared in a local scope is available only within that scope.

## 2. Named functions

```dataweave
%dw 2.0
output application/json
fun fullName(first: String, last: String) = trim(first ++ " " ++ last)
---
{ name: fullName(payload.firstName default "", payload.lastName default "") }
```

Functions reduce duplication and make business rules readable. Name functions by intent: `calculateLineTotal`, `normalizePhone`, or `isEligibleForDiscount`.

## 3. Lambdas

A lambda is an anonymous function often passed to a higher-order function.

```dataweave
%dw 2.0
output application/json
---
(payload.products default []) map ((product, index) -> {
  line: index + 1,
  label: product.name,
  total: product.price * product.quantity
})
```

You may see short forms like `map ($.name)`. The `$` and `$$` shorthand refer to the current value and index in supported lambda contexts. For maintainability, explicit parameter names are usually clearer to intermediate learners.

## 4. Scope with `do`

Use `do` to keep local declarations near a calculation:

```dataweave
%dw 2.0
output application/json
---
do {
  var items = payload.items default []
  var subtotal = sum(items map ((i) -> i.price * i.quantity))
  ---
  {
    itemCount: sizeOf(items),
    subtotal: subtotal
  }
}
```

The `do` body has a local header and a final expression. Use it when intermediate calculations belong to one transformation section.

## 5. Function composition

Break a complex rule into small steps rather than one nested expression:

```dataweave
%dw 2.0
output application/json
fun lineTotal(line) = (line.quantity default 0) * (line.unitPrice default 0)
fun isBillable(line) = line.quantity > 0 and line.unitPrice >= 0
---
{
  total: sum((payload.lines default [] filter ((line) -> isBillable(line))) map ((line) -> lineTotal(line)))
}
```

If operator precedence makes a chain difficult to read, use named intermediate variables or parentheses. Verify the exact expression in your editor.

## 6. Recursive functions

Recursion can process nested structures, but it can be harder to reason about and may be expensive. Prefer built-in functions such as `flatten`, `flatMap`, or `mapObject` when they express the operation clearly. Use recursion only when the data shape truly calls for it, and test deep and empty inputs.

## 7. Reusable functions in modules

A reusable module can export functions and types for import by other DataWeave scripts. Keep a shared function's inputs, output, null behavior, and errors explicit. Avoid hidden dependence on the calling flow's variables.

## Practice examples

### Example 7 — Reusable tax calculation

```dataweave
%dw 2.0
output application/json
fun tax(amount, rate) = amount * rate
---
{
  net: payload.amount,
  tax: tax(payload.amount, 0.1),
  gross: payload.amount + tax(payload.amount, 0.1)
}
```

### Example 8 — Normalize a person

```dataweave
%dw 2.0
output application/json
fun clean(value) = trim((value default "") as String)
---
{
  firstName: clean(payload.firstName),
  lastName: clean(payload.lastName),
  email: lower(clean(payload.email))
}
```

## Function design checklist

- Does the name describe the business rule?
- Are inputs and expected types clear?
- Is missing/null behavior intentional?
- Can the function be tested independently?
- Does it return a value instead of relying on hidden side effects?
