# 19.3 — Configure MySQL Connection in Anypoint Studio

## 1. Add the Database Connector

1. Open the Mule project in Anypoint Studio.
2. In the Mule Palette, select **Search in Exchange** if Database Connector is not already available.
3. Add the Database Connector module for your Mule runtime/Studio version.
4. Drag a Database operation such as **Select** onto a flow. Use the quick-fix prompt or Global Elements to create the Database Config.
5. Choose **MySQL Connection** for the provider.
6. Configure the MySQL JDBC driver via the driver/library option Studio provides, or as a Maven dependency compatible with your connector/runtime.
7. Enter host, port, database/schema, user, and password from your local environment.
8. Click **Test Connection** and resolve issues before continuing.

Official walkthrough: [Configure a Database Connection](https://docs.mulesoft.com/db-connector/latest/database-connector-connection).

## 2. What the connection fields mean

| Field | Example | Meaning |
|---|---|---|
| Host | localhost | Network address of MySQL |
| Port | 3306 | MySQL TCP port, unless changed |
| Database | mule_learning | Schema to use |
| User | mule_app | Restricted application account |
| Password | supplied securely | Authentication secret |
| Driver | connector-compatible MySQL JDBC driver | Java database driver |

Studio's MySQL Connection provider constructs the relevant JDBC settings. The Generic Connection alternative requires a JDBC URL and driver class. Prefer the explicit MySQL provider when it meets your needs.

## 3. JDBC driver dependency

Studio versions and Database Connector versions may guide you to a specific driver. Select a supported driver version in Studio's configuration wizard or use the dependency recommended for your runtime. Do not blindly copy an old connector's driver version from a random tutorial.

For Connector-managed projects, the dependency pattern typically resembles:

~~~xml
<dependency>
    <groupId>com.mysql</groupId>
    <artifactId>mysql-connector-j</artifactId>
    <version>REPLACE_WITH_SUPPORTED_VERSION</version>
</dependency>
~~~

This is a pattern, not a complete driver declaration: use the actual supported version and make sure the JDBC driver is visible to the Mule runtime. Consult [MuleSoft's database connection setup guide](https://docs.mulesoft.com/db-connector/latest/database-connector-connection) and the [MySQL Connector/J documentation](https://dev.mysql.com/doc/connector-j/en/).

## 4. Keep secrets outside source control

Use environment-specific configuration and secure properties/secret management for database passwords. Do not commit local passwords, production credentials, or unencrypted secrets to `mule-artifact.json`, XML files, `pom.xml`, or Git history.

For a local learning project, property placeholders may look like:

~~~properties
db.host=localhost
db.port=3306
db.name=mule_learning
db.user=mule_app
db.password=replace_me_locally
~~~

If you use a secure property mechanism, the password value must be encrypted and configured as the corresponding secure-property reference. The plain example above is only a placeholder illustration; keep the local file out of source control.

## 6. XML shape — illustrative only

Studio generates connector XML and namespaces according to the module version. A simplified configuration can look like:

~~~xml
<db:config name="MySQL_Database_Config">
    <db:my-sql-connection
        host="${db.host}"
        port="${db.port}"
        user="${db.user}"
        password="${secure::db.password}"
        database="${db.name}" />
</db:config>
~~~

Treat this as a shape to compare against the XML generated by your Studio version, not a guaranteed drop-in full configuration. Attribute/element details can vary by connector release and secure-property setup.

## 7. Test the connection

- Confirm MySQL service is running.
- Confirm the schema exists and the user has grants.
- Verify host and port from the machine/container where Mule runs.
- Confirm JDBC driver compatibility and visibility.
- Click **Test Connection** in Studio.
- Add a Select operation with `SELECT 1 AS connection_test` and run the project.

## 8. Common connection errors

| Symptom | Check |
|---|---|
| Connection refused | Server state, host, port, firewall, container networking |
| Access denied | Username/password, account host pattern, grants |
| Unknown database | Schema spelling and creation |
| No suitable driver / class not found | Correct connector-compatible JDBC driver and runtime visibility |
| SSL/TLS handshake error | Server TLS requirements, connector/JDBC options, trust configuration |
| App starts locally but fails on deploy | Deployment network reachability, secrets, runtime compatibility, allowlists |
