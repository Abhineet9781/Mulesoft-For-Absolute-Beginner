# 19.2 — Install MySQL and Prepare the Database

## 1. Prerequisites

You need a running MySQL Server instance, a SQL client such as MySQL Workbench or the mysql CLI, and Anypoint Studio with Mule 4. Keep MySQL listening on a local interface for this development POC. Follow the official documentation for your operating system and version.

- [MySQL Server documentation](https://dev.mysql.com/doc/)
- [MySQL Workbench documentation](https://dev.mysql.com/doc/workbench/en/)

## 2. Create the schema and table

Run this SQL in your local development database:

~~~sql
CREATE DATABASE IF NOT EXISTS mule_learning
  CHARACTER SET utf8mb4
  COLLATE utf8mb4_0900_ai_ci;

USE mule_learning;

CREATE TABLE IF NOT EXISTS employees (
    id BIGINT NOT NULL AUTO_INCREMENT,
    first_name VARCHAR(100) NOT NULL,
    last_name VARCHAR(100) NOT NULL,
    email VARCHAR(255) NOT NULL,
    department VARCHAR(100) NOT NULL,
    salary DECIMAL(12, 2) NOT NULL,
    created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP
        ON UPDATE CURRENT_TIMESTAMP,
    PRIMARY KEY (id),
    UNIQUE KEY uk_employees_email (email),
    KEY idx_employees_department (department)
);
~~~

If you use an older MySQL version that does not recognize the chosen collation, select a collation supported by that server (for example, `utf8mb4_unicode_ci`). Confirm the server version first.

## 3. Create a least-privilege application user

Create a separate account for the Mule local app. Replace the host and secret for your environment. The password below is a placeholder pattern: generate your own secret and do not commit it.

~~~sql
CREATE USER 'mule_app'@'localhost' IDENTIFIED BY 'REPLACE_WITH_A_STRONG_LOCAL_PASSWORD';

GRANT SELECT, INSERT, UPDATE, DELETE
ON mule_learning.employees
TO 'mule_app'@'localhost';

FLUSH PRIVILEGES;
~~~

If Mule runs in a container, `localhost` inside that container is the container itself, not the host MySQL server. Use the correct Docker service name or reachable database hostname and a matching restricted MySQL account host pattern. Do not solve connectivity by granting broad privileges to every host.

## 4. Insert sample rows

~~~sql
USE mule_learning;

INSERT INTO employees
(first_name, last_name, email, department, salary)
VALUES
('Asha', 'Sharma', 'asha.sharma@example.test', 'Engineering', 85000.00),
('Ravi', 'Mehta', 'ravi.mehta@example.test', 'Finance', 72000.00),
('Neha', 'Kapoor', 'neha.kapoor@example.test', 'Engineering', 91000.00);
~~~

Emails use the reserved `.test` domain for sample data.

Verify:

~~~sql
SELECT id, first_name, last_name, email, department, salary
FROM employees
ORDER BY id;
~~~

## 5. Test connection details

Default local values often look like this, but use your actual installation values:

| Setting | Example |
|---|---|
| Host | localhost |
| Port | 3306 |
| Schema | mule_learning |
| User | mule_app |
| Password | your local secret |

Test MySQL with the SQL client first. If the database client cannot connect, troubleshoot server status, hostname/port, grants, password, TLS, and network reachability before configuring Mule.
